KG-RAG · Step-by-Step Sequence
Two phases: Ingestion (once) + Query (every question)
Phase A Ingestion — runs ONCE when you upload the PDF
1
PDF Text Extraction
PyPDF reads the uploaded PDF page by page and extracts raw text from each page.
You (PDF) ──► PyPDF ──► Raw text per page
2
Chunking
Text is split into overlapping windows of ~400 words (configurable). Each chunk keeps metadata: chunk_id, page_number, preview text. Overlap of 60 words prevents context being cut at chunk boundaries.
Raw text ──► Chunker ──► chunks[ ] — list of {id, page, text}
3
Entity + Relation Extraction (one Claude Haiku call per chunk)
For each chunk, Claude Haiku is prompted to extract structured JSON with entities (id, label, type, description) and relationships (from, to, type, description). This runs in a loop — 1 API call per chunk.
Each chunk text ──► Claude Haiku ──► { entities: [ ], relationships: [ ] }
4
Graph Construction — NetworkX + Neo4j
Each extracted entity becomes a node. Each relationship becomes a directed edge. Nodes store the chunk_ids they came from — this is the bridge between the graph and the vector store. Both NetworkX (in-memory) and Neo4j (if connected) are updated simultaneously.
entities + rels ──► NetworkX DiGraph + ──► Neo4j (MERGE nodes/edges)
Node properties stored: label, type, description, chunk_ids[ ]
Edge properties stored: type (e.g. DEFINES, GOVERNS), description
5
Chunk Embedding ← your understanding had a small gap here
The RAW TEXT CHUNKS (not the graph) are embedded using sentence-transformers (all-MiniLM-L6-v2, runs locally, no API key). Each chunk becomes a 384-dimensional float vector. All vectors are stored in a Python list in memory (numpy arrays).
chunks[ ] text ──► sentence-transformers ──► embeddings[ ] — list of 384-dim vectors
⚠️ Correction to your understanding: The Knowledge Graph is NOT embedded. Only the text chunks are. The graph is kept as a separate structure (NetworkX + Neo4j). The connection between graph and vectors is the chunk_ids property stored on each graph node.
Phase B Query — runs every time you ask a question
6
Query Embedding
Your question is embedded using the same sentence-transformer model, producing a 384-dim vector. Must use the same model as Step 5 so vector spaces match.
"What is the LTV threshold?" ──► sentence-transformers ──► query_vector [384-dim]
7
Cosine Similarity → Top-K Chunks
Cosine similarity is computed between the query vector and every chunk embedding. Chunks are ranked by score. Top-3 (configurable) are returned with their page number and score. This is pure numpy — no external vector database needed.
query_vector vs embeddings[ ] ──► top-3 chunks with scores
Formula: cosine(q, c) = (q · c) / (|q| × |c|)
Returns: chunk text + page_number + similarity score (0–1)
8
Graph Context Lookup (this is the KG part of KG-RAG)
Using the chunk_ids from the top-k chunks, the system walks the NetworkX graph and finds all nodes whose chunk_ids overlap. For each matched node, it also retrieves its outgoing edges (relationships). This builds a structured text summary of the relevant graph neighbourhood.
top-k chunk_ids ──► NetworkX lookup ──► graph_context (text summary)
Example graph_context output:
• [Rule] LTV Threshold: defines loan-to-value ratio limits
  → APPLIES_TO → Residential Mortgage
• [Concept] Risk Weight: capital charge percentage
  → GOVERNED_BY → ERBA Rule §IV.A.2.c
9
Context Assembly
All retrieved information is assembled into a single prompt context: graph context (structured entities + relations) + top-k chunk texts (with page numbers) + the original user question.
Prompt structure:
[Graph Context] ← entities + relations
[Page 4, score=0.92] chunk text…
[Page 7, score=0.87] chunk text…
[Page 2, score=0.81] chunk text…
Question: What is the LTV threshold?
10
Answer Generation — Claude Haiku
Claude Haiku receives the full assembled context and generates a grounded answer with page citations. The system prompt instructs it to only use information from the provided context and to cite page numbers.
assembled context + question ──► Claude Haiku ──► Cited answer
