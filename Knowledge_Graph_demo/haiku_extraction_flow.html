How Claude Haiku Extracts Entities & Relationships
Per-chunk extraction — prompt engineering + structured JSON output
Step 1 — The input chunk (400 words of PDF text)
"The Basel III framework requires Category I banks to maintain a minimum CET1 ratio of 4.5%. The Federal Reserve oversees compliance and may impose additional surcharges on G-SIBs (Global Systemically Important Banks) up to 2.5%..."
Step 2 — What we send to Claude Haiku (prompt + chunk)
SYSTEM: You are an expert at extracting structured knowledge from regulatory text. Return ONLY valid JSON. No explanation. No markdown. USER: Extract entities and relationships from this text. Return this exact JSON structure: { "entities": [ {"id", "label", "type", "description"} ], "relationships": [ {"from", "to", "type", "description"} ] } Entity types: Person | Organization | Concept | Rule | Location | Event | Other Relationship types: use CAPS_VERB_PHRASE (e.g. DEFINES, APPLIES_TO, REQUIRES) TEXT: "The Basel III framework requires Category I banks to maintain..."

Key things to understand
🔁Loops over every chunk: If your PDF has 80 chunks → 80 Claude Haiku API calls during ingestion
🧠Claude doesn't need training on your doc: It reads the chunk text fresh each time and uses its language understanding to identify entities
📐Prompt is everything: The JSON schema in the prompt forces structured output — change the schema and you change what gets extracted
🔗chunk_ids is the bridge: Each node remembers which chunk it came from — this is how vector retrieval and graph lookup connect later
🔀Same entity across chunks: If "Federal Reserve" appears in chunk 7 and chunk 23, NetworkX merges them (MERGE logic) and stores chunk_ids=[7, 23]
💰Cost: Claude Haiku is ~$0.25/M input tokens. 80 chunks × 600 tokens = 48K tokens ≈ $0.012 total
